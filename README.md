# Монополія Україна 4.0 — Firebase Mini App MVP

## Запуск
1. Створіть публічний репозиторій GitHub і завантажте `index.html`, `style.css`, `app.js` у корінь.
2. У GitHub Settings → Pages виберіть Deploy from branch → main → /root.
3. У Firebase Console проєкту `monopoly-fc387` відкрийте Authentication → Sign-in method → Anonymous → Enable.
4. У Realtime Database → Rules вставте `database.rules.json` і натисніть Publish. **Ці правила лише для приватного тестування: будь-який анонімно авторизований користувач може змінити будь-яку кімнату.** Не використовуйте їх для публічного релізу.
5. У Firebase Authentication → Settings → Authorized domains додайте домен GitHub Pages, якщо це потрібно для вашого сценарію входу.
6. У BotFather відкрийте вашого бота та налаштуйте Menu Button / Mini App URL на HTTPS-адресу GitHub Pages.
7. Для тестування відкрийте гру на двох телефонах, створіть кімнату та введіть її код на другому пристрої.

## Обмеження MVP
- Підтримуються лобі на 2–6 гравців, 4 режими з різними стартовими балансами, поле з 40 клітинками, купівля міст, оренда, податки, бонуси/штрафи, черговість ходів, банкрутство.
- Немає будинків, готелів, аукціонів, обмінів, карток повного набору, справжньої логіки в'язниці та повних класичних правил.
- Після початку партії новий учасник приєднатися не може; той самий Firebase anonymous UID може повернутися після перезавантаження в тому самому браузері, якщо його сесія збереглася.
- Ігрові дії перевіряються в браузері, а не довіреним сервером. Учасники з доступом до бази можуть підміняти стан гри; кубики генеруються на клієнті. Для публічного релізу потрібні серверні перевірки (наприклад Cloud Functions) і суворі правила доступу.
- Розміщення лише статичних файлів на GitHub Pages не гарантує безпечної ідентифікації Telegram-користувача. Ім'я з Telegram використовується тільки для відображення.
- Немає автоматичного очищення старих кімнат.
